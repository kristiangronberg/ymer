# Lens: amendment ripple

The plan carries amendment markers: dated, attributed
`> **Amended (<source>, <date>):**` notes recording decisions added,
widened or changed after plan text existed. Their grammar is write-plan's
(`<plugin root>/skills/write-plan/SKILL.md`, § Task Structure, the
amendment marker) and the sweep each one owes is write-plan's recipe
(`<plugin root>/skills/write-plan/cases.md`, § Task Structure, the
amendment's footprint recipe). Read both before you start.

- Walk every marker, and read every site against the decision's latest
  statement, which the grammar says how to find.
- For each marker, sweep the decision's footprint by the recipe, over
  the corpus it names.
- Flag every site whose statement disagrees with the marker's final
  statement, narrowing included: after a scope reduction, a site still
  claiming the wider scope is a ripple hit.
- Severity: important by default; critical when the disagreement changes
  delivered content or behaviour (a payload the implementer lands
  verbatim, a README or doc fragment, a gate's corpus or expected
  count).
