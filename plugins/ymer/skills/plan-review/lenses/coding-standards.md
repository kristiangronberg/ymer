# Lens: coding standards and idioms

- The plan header names a coding-standards companion skill, and the run
  data carries its name. Read that skill: a coding-standards companion
  is the front's own, not this plugin's, so load it by that name the way
  the front loads its own skills, and if it will not load, say so in
  your findings rather than reviewing against a guessed rubric. Read its
  siblings too where the plan touches what they cover (a diagrams file
  when the plan touches diagrams, say). That skill is your whole rubric:
  import no rule from another language's standards.
- Check that the plan specifies every artifact that skill requires of a
  plan, and flag any step that prescribes something it forbids.
- Flag non-idiomatic patterns the plan would introduce, judged against
  that skill and against the sibling modules the plan sits beside: open
  them and compare.
