# Implementing — cases

The cases of the implement skill, moved here byte for byte from `SKILL.md`, which keeps the intent and the spine and names this file under every heading that has entries here. The headings are `SKILL.md`'s own; read a section's entries at the moment that section runs.

## Drift Valve

  No `implemented.md` is written: nothing was implemented to record. Its
  absence is **not** how a later session learns that — an earlier cycle's
  file may still be standing — so the state is read rather than inferred:
  review § Input item 2 runs the commit-order test that tells a live route
  from a consumed one, and `plan.md`'s ticks are the resume point. No new
  grammar is minted here: the marker and the `Unreviewed:` line are the
  ones review's closes already write.
  Never improvise architecture mid-implementation, and never let the
  record fall behind the code.

## Verify

Ripple sweeps and verification greps run in this phase are sweeps: run
the plan's gates as written, and build any ad-hoc list per the sweep
skill — recall-first, corpus per
sweep rule 2 (whole minus named exclusions, never an allowlist of
expected sites), and never narrower than the plan's own gates. An
ad-hoc gate's expected value — a count, a KEEP list, a delta — is
measured or derived in this session, never typed from memory
(measured, never typed: write-plan's Grounding). Rule 4's
falsifiability requirement stands over the plan's gates too, not only
the ad-hoc ones: run each zero-hit gate's paired non-zero assertion
here, in this session and this shell, before its zero counts — a
pairing observed at plan time cannot catch this session's own mangling
of the pattern. A zero-hit gate that arrives with no pairing gets one
supplied before it is trusted.
